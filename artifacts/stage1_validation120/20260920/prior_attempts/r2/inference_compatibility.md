# 本轮补评的 P5 历史推理兼容性

模型固定为原 validation60 选出的 Best；没有重新训练、更新参数或使用 validation120 重选 checkpoint。

首轮 r1 使用当前 evaluator 原样评测 P5 seed1，120例均完成，但旧60例的 makespan 0/60 复现，因此被控制器拒收，未继续后续模型，也不进入正式比较。

历史代码（git commit `9829b87`）显示 P5 原评测向循环选择编码器传入前一步策略动作，且非活动飞机对应动作输出为 -1。后续实现同时改为环境维护的历史动作并保留非活动行。checkpoint 的模型权重完全兼容，参数名称和形状均无遗漏，但这些无参数的推理行为没有记录在旧 checkpoint 契约中。

在保持模型、当前物理环境、数据、tau 和解码方式不变的两个案例对照中：

| 推理接口 | case_0018 | case_0027 |
|---|---:|---:|
| 历史记录 | 10512 | 8971 |
| 当前接口 | 11759 | 8979 |
| 仅恢复前一步动作历史 | 11063 | 8949 |
| 同时恢复前一步动作历史及非活动行 -1 | 10512 | 8971 |

2个案例对照证据见 `provenance/probe_summary.json`，历史代码片段见 `provenance/august_eval_excerpt.txt`。本次使用独立评测适配器按模型 SHA256 锁定原推理接口：P5 恢复历史接口，四个学习基线保持其训练和原评测使用的环境历史接口。所有模型共用一个 validator 和完全相同的物理环境与120例数据。

两个案例只是启动前兼容性验证。正式验收要求每个 checkpoint 的120例均完成、模型和案例指纹正确、无超时/循环终止，且旧60例的 makespan 全部逐例相等；以 `audits/*.json` 和 `state.json` 为最终证据。任何偏差会停止后续队列，不会通过放宽阈值制造一致结果。

这是固定历史学习策略的扩展评测，不能据此隔离网络架构或历史输入实现的因果贡献。
